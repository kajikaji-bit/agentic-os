# Set Timer

前提: `HERDR_ENV=1` と Bash 4.3 以降、Herdr が使える。`date -d` も必要。

## 手順

1. 観測と通知先を決める
2. monitor タブで起動する
3. 検出したイベントを通知する

### 1. 観測と通知先を決める

[herdr](../herdr/SKILL.md) に従い、この会話の Herdr セッション名とエージェントの `pane_id` を特定する。環境変数の ID が古い場合は `agent list` と `pane read` で照合する。監視する対象、ジョブを区別する名前、検知時の通知文を決める。

一度きりなら指定時刻に通知して終了する。繰り返す場合は固定秒数で次の時刻へ進む。過去の時刻を指定した一度きりのタイマーは通知せず終了する。繰り返しでは未来の周期へ進め、過ぎた回をまとめて通知しない。

時刻の例は `today 15:00`、`+30 minutes`、`monday 10:00`。タイムゾーンは実行環境のものを使い、依頼と食い違うときは確認する。繰り返し周期は毎日なら86400秒、毎週なら604800秒。固定秒数なので夏時間をまたぐ場合も同じ秒数で進む。

### 2. monitor タブで起動する

同じワークスペースの `monitor` タブのシェルを使う。なければ作り、返された `.result.root_pane.pane_id` を起動先とする。

```bash
herdr --session <セッション名> tab list --workspace <ワークスペースID>
herdr --session <セッション名> tab create --workspace <ワークスペースID> --label monitor --cwd <プロジェクトの絶対パス> --no-focus
```

次の値を埋め、`herdr --session <セッション名> pane run <monitorペインID> <起動コマンド>` で、そのシェルへ送る。パスや通知文はシェル引数として引用する。

```bash
bash '<このスキルの絶対パス>/scripts/monitor.sh' \
  '<Herdr セッション名>' '<通知先 pane_id>' 'timer-once' \
  '<date -d が解釈する時刻の式>' \
  '指定された時刻になったことをユーザーへ知らせてください。' &
monitor_pid=$!
```

引数は順にセッション名、通知先、監視名、時刻の式、通知文。続けて周期の秒数と `all` または `weekdays` を省略可能な引数として指定できる。例えば末尾に `86400 weekdays` を付けると平日のみ毎日通知する。 対象ごとにジョブを起動し、監視名と PID を保存する変数を分ける。標準出力はリダイレクトしない。既定は60秒間隔で、変更する場合は起動コマンドの先頭に `MONITOR_INTERVAL=10` のように付ける。

例えば平日の18時なら、時刻の式を `today 18:00` にし、通知文の後に `86400 weekdays` を付ける。待機中もログを出し、指定時刻に到達したときにも観測する。タイマーの `MONITOR_INTERVAL` は正の整数秒で指定する。

停止するときは `monitor` タブの同じシェルで実行する。

```bash
jobs -l
kill "$monitor_pid"
```

### 3. 検出したイベントを通知する

起動時に `event=started target=... interval=60s`、観測ごとに `event=checked changes=0` のように標準出力へログを出す。イベントを検知したときは `detected count=...` と、送信後の `sent pane=...` も出す。

```text
2026-09-21T11:01:00+09:00 INFO monitor=timer-once event=checked changes=0
```

起動時の通知文と観測結果を次の形式にし、`herdr --session <セッション名> agent prompt <pane_id> <メッセージ>` で一度送る。応答完了を待つ `--wait` は付けない。

```text
[monitor:timer-once]
指示: 指定された時刻になったことをユーザーへ知らせてください。
観測:
- 検出した対象
```

一度きりのタイマーは通知後に終了し、定時のタイマーは次の周期まで続ける。通知ID、再試行、通知先の消失検知は設けない。イベントの扱いは使用者に委ねる。
