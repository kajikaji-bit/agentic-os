# Execute

agentic-runtime は、一つのタスクを順序付きのステップからなるワークフローに従って完了へ運ぶ。

- ワークフローは YAML が正本、ロール・チェックリスト・ナレッジは Markdown が正本
- `log.jsonl` はコアだけが記録する監査記録
- `state` と `current_step` はタスクの状態と進行中のステップの名前を持つ、ログの写し
- メインエージェントが指示に従い、各ステップの仕事をする
- メインエージェントが完了コマンドでステップを完了し、Stop Hooks が次のステップを開始して指示を送る

plugin が持つのは CLI とコアだけである。アセットは利用リポジトリが持つ。以下の `agentic-runtime` コマンドは `<この Skill directory>/scripts/agentic-runtime` として実行する。このファイルは plugin root の `bin/agentic-runtime` への相対シンボリックリンクであり、利用リポジトリへ CLI をコピーしたり PATH を設定したりしない。

コマンドを実行するのはメインエージェントである。タスクとステップの状態はコマンドが変え、Stop Hooks は次のステップを開始して指示を送る。

実行できるコマンドは `agentic-runtime --help`、`agentic-runtime <command> --help` で確かめる。この手順書はコマンドの一覧を持たない。

ワークフローそのものを新しく作る、または既存のワークフローを変えるときは `agentic-runtime:plan` に従う。

## 明示された /agentic-runtime:execute は実行する

メッセージが `/agentic-runtime:execute <具体的な依頼>` で始まるか、「agentic-runtime で <具体的な依頼>」と命じられた場合はタスクの作成の依頼として扱う。

1. `.agents/workflows/` の `name` と `description` を確かめ、依頼に最も近いワークフローを一つ選ぶ。
2. 合うワークフローがあれば `task create --workflow` を実行する。
3. 合うワークフローがなければ `task create` だけを実行し、`agentic-runtime:plan` に従ってワークスペースの `workflow.yaml` へそのタスクのステップを書く。
4. タスクを作成するコマンドが成功したら、その応答を直ちに終了する。
5. Hooks の指示を受け取るまで、進行中のステップの成果物の作成、セルフチェック、完了コマンドを実行しない。

```sh
agentic-runtime task create search-filter --workflow software-delivery
```

ワークスペースは `workspace/<YYYY>/<YYYYMM>/<タスク ID>/` に作られる。タスク ID は作成した日（JST）とタスク名から `<YYYYMMDD>-<task-name>` の形で決まり、以後のコマンドはタスク ID でタスクを指す。`task.md` はタスク ID の見出しだけを持ち、`workflow.yaml` はステップの契約、`state` と `current_step` はタスクの状態と進行中のステップの名前を持つ。ステップのディレクトリとアセットは、そのステップを開始したときに揃う。

## 指示に従って進める

指示は、ワークフローと進行中のステップが指定したルール、ワークスペースと進行中のステップのディレクトリ、任意のロール、ステップの `description`、ルールを含む `using`・`read`・チェックリストのパス、成果物、承認の要否と完了コマンドを渡す。`## ワークスペース` の節はワークスペース自体を絶対パスで示し、その中にあるステップ・アセット・成果物はワークスペース起点の相対パスで示す。

メインエージェントは次の順で進める。

1. 指示の `read` を読み、`using` のスキルに従う。
2. 成果物を作る。
3. チェックリストの項目を一つずつセルフチェックし、満たす項目にだけチェックを付ける。満たさない項目は未チェックのまま残し、成果物を直してから付け直す。
4. `approval: required` なら[承認を依頼する](#承認を依頼する)。承認を受け取るまで先へ進まない。
5. 指示に示された `step complete` を実行する。未達の完了条件が返ったらすべて直して同じコマンドを再実行する。成功したらターンを終え、Hooks が次の指示を渡す。

完了コマンドは成果物、チェック、承認を一度に判定する。最後のステップを完了したあとは、Hooks がタスクをクローズする。

ワークフローは直線的に進む。指示は一つのステップにつき一度だけ届く。

## 承認を依頼する

`approval: required` のステップは、承認者本人の発言を受け取るまで完了できない。承認する人間の返答を待つため、このステップは必ず複数のターンにまたがる。1 ターンで終わらせようとしない。

1. 成果物を作りセルフチェックを終えたら、ユーザーへ承認を依頼する発言をしてターンを終える。承認を依頼するコマンドは無い。チャットで依頼する。
2. ユーザーの承認の発言が実際に届くまで完了コマンドを再実行しない。要約・言い換え・推測で承認の発言を作らない。
3. 承認の発言が届いたら、その発言をそのまま `step complete --approval-evidence` へ渡す。
4. 修正を依頼されたら直して 1 へ戻る。

承認を待つあいだ、Hooks は同じ指示を送らない。指示は一つのステップにつき一度だけ届く。

## セッションを引き継ぐ

そのタスクの仕事は、一つのセッションが担当する。別のセッションへ引き継ぐときは、引き継ぐ側のセッションで `agentic-runtime session attach <task-id>` を実行する。担当が移ると、Hooks はそのセッションへ指示を送る。

## 未着手の計画を組み直す

依頼者が未着手のステップの追加・更新・削除を依頼したら、タスクの `workflow.yaml` の未着手だけを直す。着手済みのステップは元に戻す。書き方は `agentic-runtime:plan` に従う。アセットは次に開始するステップがそのときのワークフローから揃えるので、揃え直すコマンドは無い。直したら完了コマンドは実行せず応答を終える。Hooks は未着手が変わった直後に指示を送らない。
